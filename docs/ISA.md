# ISA Manual

## Общие параметры

| Параметр | Значение |
| --- | --- |
| Разрядность данных и команды | 16 бит |
| Регистры | 8 × 16 бит (R0–R7) |
| R0 | при чтении всегда 0, запись игнорируется |
| R7 | адрес возврата для `JAL` (по соглашению) |
| Сброс | синхронный, все регистры, PC и конвейер в 0 |
| Память | гарвардская: команды и данные в разных адресных пространствах |
| Адресация | пословная: адрес — номер 16-битного слова |
| Прерывания | нет, устройства опрашиваются программой |

**Почему так.** 16 бит хватает на все три задачи: F(24) = 46368 — наибольшее число Фибоначчи, которое помещается в слово; символ ASCII и столбец матрицы занимают по байту; адрес RAM 8 бит. Короткая команда даёт простой декодер, а 8 регистров кодируются 3 битами, поэтому в слово помещаются три регистра и код функции. Цена — короткие константы (6 бит со знаком), поэтому для 16-битных констант есть пара `LUI`/`LLI` и псевдокоманда `LI`.

## Форматы команд

```
 15    12 11    9 8     6 5     3 2     0
+--------+-------+-------+-------+-------+
|   op   |  rd   |  rs1  |  rs2  | funct |   R — регистр-регистр
+--------+-------+-------+-------+-------+
|   op   |  rd   |  rs1  |     imm6      |   I — с константой, -32..31
+--------+-------+---+---+---------------+
|   op   |  rd   | 0 |      imm8         |   U — 8-битная константа
+--------+-------+---+-------------------+
|   op   |            addr12             |   J — абсолютный адрес ROM
+--------+-------------------------------+
```

## Система команд

| Мнемоника | op | Формат | Действие | Биты (пример) |
| --- | --- | --- | --- | --- |
| `ADD rd, rs1, rs2` | 0 | R, funct 0 | rd = rs1 + rs2; флаги Z, N, C | `0000 ddd sss ttt 000` |
| `SUB rd, rs1, rs2` | 0 | R, funct 1 | rd = rs1 − rs2; C = нет заёма | `0000 ddd sss ttt 001` |
| `AND rd, rs1, rs2` | 0 | R, funct 2 | rd = rs1 & rs2 | `0000 ddd sss ttt 010` |
| `OR rd, rs1, rs2` | 0 | R, funct 3 | rd = rs1 \| rs2 | `0000 ddd sss ttt 011` |
| `XOR rd, rs1, rs2` | 0 | R, funct 4 | rd = rs1 ^ rs2 | `0000 ddd sss ttt 100` |
| `NOT rd, rs1` | 0 | R, funct 5 | rd = ~rs1 | `0000 ddd sss 000 101` |
| `SHL rd, rs1, rs2` | 0 | R, funct 6 | rd = rs1 << rs2[3:0] | `0000 ddd sss ttt 110` |
| `SHR rd, rs1, rs2` | 0 | R, funct 7 | rd = rs1 >> rs2[3:0], логический | `0000 ddd sss ttt 111` |
| `ADDI rd, rs1, imm` | 1 | I | rd = rs1 + sext(imm6) | `0001 ddd sss iiiiii` |
| `LW rd, imm(rs1)` | 2 | I | rd = MEM[rs1 + sext(imm6)] | `0010 ddd sss iiiiii` |
| `SW rd, imm(rs1)` | 3 | I | MEM[rs1 + sext(imm6)] = rd | `0011 ddd sss iiiiii` |
| `BEQ ra, rb, метка` | 4 | I | если ra = rb: PC = PC + 1 + sext(imm6) | `0100 aaa bbb iiiiii` |
| `BNE ra, rb, метка` | 5 | I | если ra ≠ rb: переход | `0101 aaa bbb iiiiii` |
| `BLT ra, rb, метка` | 6 | I | если ra < rb (со знаком): переход | `0110 aaa bbb iiiiii` |
| `JMP метка` | 7 | J | PC = addr12 | `0111 aaaaaaaaaaaa` |
| `JAL метка` | 8 | J | R7 = PC + 1; PC = addr12 | `1000 aaaaaaaaaaaa` |
| `JR rs1` | 9 | I | PC = rs1 | `1001 000 sss 000000` |
| `LUI rd, imm8` | A | U | rd = imm8 << 8 | `1010 ddd 0 iiiiiiii` |
| `LLI rd, imm8` | B | U | rd = (rd & 0xFF00) \| imm8 | `1011 ddd 0 iiiiiiii` |
| **`FONT_RENDER rd, rs1, rs2`** | **C** | **R** | **rd = столбец rs2 глифа символа rs1 — кастомная** | `1100 ddd sss ttt 000` |
| `HALT` | F | J | остановить процессор | `1111 000000000000` |

Коды `0xD` и `0xE` свободны. Незнакомый код останавливает процессор, как `HALT`.

### Флаги

Регистр флагов `{Z, N, C}` обновляют только команды группы `op = 0`. Z — результат равен 0; N — старший бит результата; C — перенос у `ADD`, отсутствие заёма у `SUB` (как в ARM). Условные переходы на флаги не смотрят: они сравнивают два регистра прямо в стадии EX, поэтому между сравнением и переходом не нужна отдельная команда. Флаги выведены наружу (`dbg_flags`) и видны на временных диаграммах.

### Кастомная инструкция FONT_RENDER

```
FONT_RENDER rd, rs1, rs2     rd = { 8'h00, FONT_ROM[(rs1 - 0x20) * 6 + rs2] }
```

- `rs1` — код ASCII, `rs2` — номер столбца глифа (0..5).
- Результат — столбец из 8 пикселей: бит 0 — верхняя строка, бит 6 — нижняя.
- Шрифт 5×7 и пустой столбец-разделитель, 64 глифа (`0x20`–`0x5F`) в Font ROM 384 × 8 бит.
- Строчные буквы и `0x60`–`0x7E` аппаратно сворачиваются на заглавные (`0x40`–`0x5E`).
- Код вне `0x20`–`0x7E` или столбец ≥ 6 дают пустой столбец.
- Выполняется за 1 такт в стадии EX, результат идёт через forwarding как у обычной команды АЛУ.

**Что ускоряет.** Без неё один столбец стоит около семи команд и обращения к памяти: вычесть `0x20`, умножить на 6 (два сдвига и сложение), прибавить столбец и базу таблицы, выполнить `LW`. Тело цикла отрисовки (32 столбца на кадр) выросло бы примерно с 11 до 17 команд. Кроме того, таблица шрифта заняла бы 384 слова RAM (192 при упаковке по два байта) из 256 доступных, и для текста почти не осталось бы места.

## Псевдокоманды ассемблера

| Псевдокоманда | Разворачивается в | Слов |
| --- | --- | --- |
| `LI rd, imm16` | `LUI rd, hi(imm)` + `LLI rd, lo(imm)` | 2 |
| `MOV rd, rs` | `ADD rd, rs, R0` | 1 |
| `NOP` | `ADD R0, R0, R0` (`0x0000`) | 1 |
| `INC rd` / `DEC rd` | `ADDI rd, rd, ±1` | 1 |
| `B метка` | `BEQ R0, R0, метка` | 1 |
| `BEQZ ra, м` / `BNEZ ra, м` | `BEQ`/`BNE ra, R0, м` | 1 |
| `BGT ra, rb, м` | `BLT rb, ra, м` | 1 |
| `CALL метка` / `RET` | `JAL метка` / `JR R7` | 1 |
| `LBEQ`/`LBNE ra, rb, м` | обратное условие через `JMP`: переход на любой адрес | 2 |
| `LBLT ra, rb, м` | `BLT +1`, `B +1`, `JMP м` | 3 |

## Карта памяти

**Память команд** — отдельное пространство: 1024 слова (`0x000`–`0x3FF`), PC 10 бит.

**Память данных:**

| Адреса | Устройство | Доступ | Кэш |
| --- | --- | --- | --- |
| `0x0000`–`0x00FF` | Data RAM, 256 слов | R/W | да |
| `0x8000`–`0x801F` | видео-буфер, 32 столбца × 8 бит | R/W | нет |
| `0xFF00` | UART `RX_DATA` — байт из очереди (чтение снимает его) | R | нет |
| `0xFF01` | UART `STATUS`: бит 0 — есть байт, 1 — передатчик свободен, 2 — переполнение | R | нет |
| `0xFF02` | UART `TX_DATA` — отправить младший байт | W | нет |
| `0xFF03` | `BUTTONS`: бит 0 — быстрее, 1 — медленнее, 2 — пауза | R | нет |
| `0xFF04` | `TIMER` — счётчик тиков (тик = `TICK_DIV` тактов) | R | нет |

Остальные адреса читаются как 0, запись в них игнорируется. Адреса 0..31 доступны как `imm(R0)`; к остальным обращаются через базовый регистр, например `LUI R5, 0xFF` → `R5 = 0xFF00`, затем `LW R1, 1(R5)` читает `STATUS`.

## Конвейер и конфликты

Пять стадий: IF → ID → EX → MEM → WB. Подробнее — [ARCH.md](ARCH.md).

| Конфликт | Как снимается | Цена |
| --- | --- | --- |
| RAW, результат АЛУ нужен следующей команде | forwarding EX/MEM → EX | 0 тактов |
| RAW через одну команду | forwarding MEM/WB → EX | 0 тактов |
| RAW через две команды | сквозная запись в регистровом файле (WB → ID) | 0 тактов |
| Load-use: команда сразу использует результат `LW` | stall: PC и IF/ID держатся, в EX идёт пузырь | 1 такт |
| Переход выполнен (решается в EX) | flush IF/ID и ID/EX | 2 такта |
| Промах кэша данных | весь конвейер заморожен | `MISS_PENALTY` тактов (4) |
| `HALT` | после него команды не выбираются; останов, когда `HALT` дошёл до WB | — |
